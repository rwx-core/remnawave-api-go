# rwx-core/remnawave-api-go

Клиент API панели Remnawave, которым владеем мы: генерируется ogen из опубликованной
OpenAPI-спеки вендора. Ни одна строка кода в `api/` не написана руками и не скопирована
из чужого SDK.

## Зачем он нужен

Вендор требует пинить SDK под версию панели. Community-SDK за ней не успевает: последний
релиз — `v3.4.4`, панель уже `3.4.5`. Проверено на 2026-10-13: `go list -m -versions
github.com/Jolymmiles/remnawave-api-go/v3` отдаёт единственную `v3.4.4`.

Полная спека панели (162 пути) при этом **не генерируется в принципе**. В 3.4.x каждая
операция описывает тело ошибки как `oneOf` без дискриминатора, а ogen такие объединения
различать не умеет: он пропускает операцию целиком. На полной спеке это 218 пропущенных
операций и ноль из нужных нам. Обе версии генератора ведут себя одинаково — v1.24.0
(текущая) и v1.19.0 (та, на которой собран community-SDK); второй вообще падает на
разборе спеки.

Поэтому клиент строится из урезанной спеки: только те операции, которыми реально
пользуется rwx-store. Это 13 операций и 27 000 строк вместо 233 000 у полного SDK.

## Что здесь лежит

| Файл | Что это |
|---|---|
| `openapi-3.4.5.json` | полная спека вендора, как есть. Её собственность Remnawave, мы её только храним |
| `tools/trim-spec.py` | строит урезанную спеку из полной: режет лишние пути и схемы, правит известные ошибки вендора |
| `openapi-trimmed.json` | результат. Это контракт, по которому сгенерирован `api/` |
| `api/` | сгенерированный клиент. Не править руками |
| `api/behaviour_test.go` | два теста, которые держат наши правки (см. ниже) |
| `ogen.json` | настройки генератора |

## Что мы поменяли относительно спеки вендора

Обе правки — в `tools/trim-spec.py`, обе зафиксированы тестами.

**1. Идентификаторы принудительно целые.** Вендор объявляет `userId` как `type: number`
без целочисленного формата. ogen честно рендерит float в путь, и `GET /api/users/12345`
уходит как `/api/users/12345.0000000000`, который панель отвергает. В спеке 3.4.4 был
`integer` — это регрессия вендора. Панель принимает целое (адаптер rwx-store передаёт
`int64`, живая проверка проходит), поэтому здесь параметр объявлен как
`integer/int64`.

**2. Тела ошибок не моделируются.** У каждой операции ответ `400` объявлен как
`oneOf [RemnawaveBadRequestErrorDto, RemnawaveValidationErrorDto]`. Объединения без
дискриминатора ogen не генерирует, поэтому такие ответы вырезаны из урезанной спеки.

Это не значит, что тело ошибки теряется. Не-2xx приходит как
`*validate.UnexpectedStatusCodeError`, у которого `StatusCode` заполнен, а
`Payload.Body` **остаётся читаемым**:

```go
var unexpected *validate.UnexpectedStatusCodeError
if errors.As(err, &unexpected) {
    body, _ := io.ReadAll(unexpected.Payload.Body) // разбираем по спеке вендора
}
```

Формы обоих DTO описаны у вендора: у `RemnawaveBadRequestErrorDto` есть `message`,
`errorCode`, `path`, `timestamp`, у `RemnawaveValidationErrorDto` — `message`,
`statusCode`, `errors[]`. Разбор тела ошибки — забота вызывающего кода, а не клиента.

## Работа с клиентом

Конструктор требует источник авторизации. Панель использует bearer, готового хелпера в
клиенте нет — интерфейс тривиальный:

```go
type bearerAuth struct{ key string }

func (a bearerAuth) Authorization(context.Context, api.OperationName) (api.Authorization, error) {
	return api.Authorization{Token: a.key}, nil
}

client, err := api.NewClient(panelURL, bearerAuth{key: apiKey})
```

Методы называются по `operationId` из спеки, поэтому с префиксом контроллера:
`UsersControllerCreateUser`, `InternalSquadControllerGetInternalSquads`,
`HwidUserDevicesControllerGetUserHwidDevices`.

## Версии

Тег релиза совпадает с версией панели: `v3.4.5` — значит клиент собран из спеки 3.4.5.
Модуль `/v3` в пути повторяет мажорную линейку панели, чтобы совпадать с раскладкой
community-SDK: переключение зависимости в rwx-store меняет только имя модуля.

## Регенерация

```sh
make generate   # пересобрать урезанную спеку и клиент
make check      # пересобрать и упасть, если что-то разошлось с закоммиченным
make test       # сборка, vet, тесты
```

Смена версии панели: положить новую полную спеку, поправить `SPEC_VERSION` в `Makefile`,
прогнать `make generate`. Если вендор переименует или уберёт нужную операцию,
`tools/trim-spec.py` остановится с ошибкой, а не урежет контракт молча.
